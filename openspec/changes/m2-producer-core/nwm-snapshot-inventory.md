## 4. 风险与不确定项

1. **补跑需最小改写为独立函数**（design.md Risks 已预判）：`_recover_missing_state_checkpoints` 是 `SHUDRuntime` 方法，读 `self.config`/`self._runtime_command()`/`self.output_dir`。快照时须改写为接受显式入参（运行目录、manifest、执行命令）的函数，模块头注明偏离。同理 `_StateCheckpointTracker.__init__` 直接读 `manifest["start_time"]`，yd 的 work manifest 须提供同名字段或在构造处适配。
2. **`producer.py` 的 `grid_signature` 链剥离面较宽**：签名校验贯穿 `_validate_direct_grid_contract_for_production` → `grid_signature_by_source_grid` → 物化调用链（L570-806、L938-1042）。剥离后 direct-grid 的"canonical 网格与 binding 一致"保护随之消失；任务 8.1 须以合成 canonical fixture 的行为测试补回等价断言，否则是净安全损失。此项在只读勘察阶段无法判定剥离后残留代码是否仍自洽，需在 2.2/8.1 实测。
3. **`base.py` 无干净的既有测试**：引用 `DownloadManifest`/`ManifestEntry`/`cycle_id_for` 的 23 个 NWM 测试文件全部是 adapter / scheduler / DB 重度文件，无一可作最小快照。任务 2.2 须**新写** manifest 结构的 roundtrip 测试（`as_dict`/`from_dict`），不列入本清单的快照行。
4. **`LocalObjectStore` 无干净的既有单元测试**：`tests/test_object_store_roots.py` 依赖 `jinja2`、`state_manager`、`services.artifacts` 与三个 adapter，剥离成本高于重写。任务 2.2 须新写 object-store 路径函数的最小测试。
5. **`direct_grid_contract.py` 无独立测试文件**：其用例散落在 `tests/test_forcing_producer.py`（如 L2683、L4292）与 mapping-builder / state-clone 测试中。清单已把 `test_forcing_producer.py` 的相关用例纳入抽取范围，但契约解析的边界用例覆盖是否足够，须在 2.2 实测后判定。
6. **抽取式行的边界在只读阶段只能到符号级**：`state_cli.py`、`runtime.py`、`test_forcing_producer.py`、`test_shud_runtime.py` 四行是"取子集"而非整文件复制。子集内部是否还牵出未列出的私有 helper（如 `runtime.py` 的 `_read_limited_text_no_follow`、`_write_text_no_follow` 等 no-follow 包装），须在 2.2/9.1 落码时按 import 闭包收敛；预判这些 helper 均为 `safe_fs.py` 薄封装，已随 `safe_fs.py` 行快照。
7. **`converter.py` 的 ERA5 分支**：`ERA5CanonicalConverterConfig`(L259) 及其转换路径与 yd 双源无关，清单标注删除；但 `evaluate_canonical_readiness`(L403) 等共享函数是否含 ERA5 专属分支，须在 7.1 落码时确认，避免删过头。
