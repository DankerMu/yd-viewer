目标布局遵循 design.md D1：全部落 `producer/src/yd_producer/<module>/<file>.py`，测试落 `producer/tests/<file>.py`。

清单约定（五条，全表适用；每条对应 §5 的一个机械检查）：

1. **枚举必须可机械再生。** `剥离点` / `抽取` / `备注` 里的符号枚举，要么写全集，要么给出再生该集合的 grep 命令并标注命中总数。不出现无标记的截断列表。
2. **抽取式行必须给传递闭包，闭包义务含模块级常量。** 标注「抽取式」的行，其 `抽取` 列包含被抽取符号直接或间接调用的全部私有 helper、异常类型**与模块级常量**（含模块级 `X = <expr>` 重绑定，如测试文件顶部的 `X = module.X` import shim），逐个给定义行号；闭包被主动切断处（如改写为显式入参）明确写出切点。模块级常量此前被漏在闭包义务之外，是 Round 2 的根因：§5 原再生方法的名字表只取 `FunctionDef`/`ClassDef`，按它复算永远显示通过。
3. **规范性动作只能写在 `剥离点` 列。** 删除 / 改写 / 内联 / 替换 / 改抛这类落码必须执行的动作，一律写进 `剥离点`；`备注` 只放理由、保留集与语义锚点，不得独家承载动作。`剥离点` 写 `无` 的行必须真的零动作。（抽取式行的 `抽取` 列是本约定的例外：它按约定 2 是规范性的。）
4. **跨行引用必须闭合。** 任一行命令删除的符号，若被**其他行保留的内容**在 pin 上以 §5 定义的**五种引用形态**（`ast.Name` / `self.<attr>` / 字符串模块路径 / `X as Y` 别名的两个名字 / 包装函数式 env 读取）之一引用，则该其他行必须点名处置（删该用例 / 改写 / 内联字面量 / 保留并说明）；处置产生的覆盖缺口一律在 §4 声明。逐行修某一行的删除集时必须回头扫引用方，否则缺陷会以跨行形状复发。
5. **符号与行号必须与 pin 的 ast 一致。** `` `符号`(Lnnn) `` 的 `Lnnn` 等于该符号的 ast `lineno`；`` `符号`(Lnnn-mmm) `` 等于 `(lineno, end_lineno)`；类成员须写成 `` `类名.方法名` `` 以免被读成模块级符号；非定义点的行号（实例化点、调用点、断言点）须显式标注是哪一种。

## 5. 枚举与闭包的再生方法

本清单的所有符号枚举可用下列命令在 pin 上机械复算（`<NWM>` = NWM 仓路径，`8ae9b8f2` = 锚点）：

- 计数型枚举：`git -C <NWM> grep -n '<pattern>' 8ae9b8f2 -- <path>`（清单内已给出 pattern 与命中总数的行，直接对比即可）。
- 抽取式行的闭包（约定 2）：把 `git -C <NWM> show 8ae9b8f2:<path>` 的输出交给 `ast` 解析，取模块级 `FunctionDef` / `AsyncFunctionDef` / `ClassDef` **以及模块级 `Assign` / `AnnAssign` 的目标名**建名字→行号表，从抽取种子出发按下列**五种引用形态**（Round 3 起，原为前两种）做广度优先传递闭包，直到不再新增；`剥离点` 与闭包的交集即"必须改写而非直接搬运"的点（如 `_runtime_command`、`FakeHydroRunRepository`、`repository=` 形参），这些点从名字表里剔除后再做闭包。
  **`Assign`/`AnnAssign` 不可省。** 只取 `FunctionDef`/`ClassDef` 的名字表看不见模块级常量，按它复算 6 个抽取式行会**逐字复现清单原文**（自证通过），却漏掉 runtime 的 5 个错误码/上限常量、test_shud_runtime 的 13 个 solver stub 源码串、test_canonical_converter 的 14 个 import shim 重绑定、test_state_manager 的 2 个 fixture 常量、state_cli 的 3 个常量。自检方法：**对同一种子集各跑一遍（名字表含 / 不含 `Assign`），两次结果的差集即被旧方法漏掉的模块级常量，该差集必须已被该行 `抽取` 列逐个列出**。
  **引用形态共五种（Round 3 扩展；前两种为原有，后三种是本轮补入的盲区）：**
  1. `ast.Name` —— 裸标识符引用。
  2. `self.<attr>` —— 实例属性引用。
  3. **`ast.Constant` 字符串模块路径** —— 形如 `"a.b.c.symbol"` 的字符串常量，取最后一段作为被引用符号，与裸标识符同权入 BFS 与约定 4 的跨行闭合。典型来源是 `monkeypatch.setattr("mod.path.name", ...)`：它在 setattr 期按属性名解析，目标符号不存在即 `AttributeError`（`raising` 默认 `True`），却对裸标识符正则与 `ast.Name` 闭包完全不可见。
  4. **`X as Y` import 别名** —— 本地绑定是 `Y`，源名是 `X`，**两个名字都进符号集**；清单里写 `` `X as Y` `` 时两个名字都算被点名。只抽 `alias.asname` 会让删除指令与引用方对不上（`_grid_signature_hash` 即此形态）。
  5. **包装函数式环境变量读取** —— `_float_env("V")` / `_env_int("V")` / `_env_flag("V")` / `_env_float("V")` / `*_from_env()` 等价于 `os.getenv("V")`，同受 design.md D4「零默认」约束，必须与裸 `os.getenv` 一并点名。只扫 `os.getenv` 会漏掉包装形态。
  **已知边界（诚实声明，不假装完备）：** 中文散文里「同一个规范动作写在 `备注` 还是 `剥离点`」无法机械判定——`删`/`改写` 等动词在两列都是自然中文，任何正则都会把 `备注` 里合法的理由陈述误判为动作。约定 3 因此只能靠人工复核，**不为它编造检查器**；本轮的做法是逐行把已发现的动作句移进 `剥离点` 并在 `备注` 只留理由。同理，符号在被删函数体内 vs 保留函数体内的归属靠 ast 顶层 span 判定，嵌套 def 与类内多层不在模型内。**第三条边界（R4A1，本轮补入）：不带点的产物 payload 键无法机械解析，五种引用形态不覆盖它，也不为它扩出第六种。** 形态 3 只认「形如 `"a.b.c.symbol"`、可按最后一段解析出符号名」的字符串常量；而 `payload["validated_grid_signature"]` 这类下标键是**不带点的裸字符串**，它引用的不是任何命名符号，而是被删函数体内某个 dict 字面量的键（此例是 producer `_direct_grid_lineage_identity` L2977/L2978 产出、tests `_assert_direct_grid_package_contract` L5139/L5140 消费）。把形态 3 放宽到「任意字符串常量」会把源码里每一个字符串都拉进跨行闭合，噪声远超信号，且没有任何 oracle 能判定哪个字符串是 payload 键；唯一能机械化的替代是为每个产物维护逐行 payload 键表，本 PR 不做（成本远超收益，且键表本身又是一份无人复核的断言）。**因此这一类只能靠人工复核**：落码时凡删除一个产出 dict 字面量键的函数，必须回头 grep 该键名在保留侧的下标读取——`git -C <NWM> grep -n '"<键名>"' 8ae9b8f2 -- <保留侧文件>`；本轮已按此法处置 `:49` 的 L5139/L5140，verifier 已独立扫过 `:47`/`:55`/`:57`/`:46` 并确认同型形态在那四行**已被声明处置**（`:55` 第 3 项 `_rekey_run_context` 的 6→2 kwargs 已写明构造期 TypeError，`:57` 已处置读侧 L5202-5204，`:46` 的 `PACKAGED_IC_*` 用点落在抽取闭包外），即本形态在本清单上的残留面为空。**不为它编造检查器**，与约定 3 同口径。
